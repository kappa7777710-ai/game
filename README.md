# Индустриальный пояс

Прототип браузерной космической экономической стратегии. Замкнутая экономика:
все товары добываются или производятся игроком, ничего не появляется «из воздуха».

## Что внутри

Всё сейчас лежит в одном файле — `index.html` (самодостаточный HTML/CSS/JS,
без сборки и зависимостей, кроме шрифтов Google Fonts по CDN).

Ключевые системы:

- **Производственные цепочки**: 19 ресурсов, 5 уровней (tier 0–4), непрерывная
  симуляция потоков (не пошаговая), реальное время с оффлайн-прогрессом
  (до 12 часов, досчитывается кусками по 30 сек при заходе).
- **Население и рабочая сила**: 4 класса рабочих (Разнорабочие / Техники /
  Инженеры / Специалисты), у каждого свои потребности в потребительских
  товарах. Продуктивность = взвешенная сумма удовлетворения по каждому
  ресурсу (вода 30%, еда 35%, одежда 20%, отдых 15% — для класса 1),
  а не строгий bottleneck по минимуму.
- **Навыки (EVE-style)**: 5 отраслей навыков, привязанных к тирам 0–4.
  Прокачка одного навыка одновременно, очки навыков (SP) генерируются
  самими производственными зданиями (пропорционально их количеству) плюс
  Академия. Прокачанный навык увеличивает скорость и снижает потребность
  в рабочих для своего тира.
- **Иконки**: у каждого ресурса, класса населения и отрасли навыков —
  свой SVG-пиктограм (объект `ICONS` в скрипте).
- Сохранение — в `localStorage`, версия схемы — `SAVE_KEY` (сейчас `v5`),
  при несовместимых изменениях данных версию нужно бампать, чтобы не
  ловить сломанные старые сейвы.

## Как запустить

Файл ничего не требует — просто открыть `index.html` в браузере.
Для удобной разработки лучше поднять локальный сервер (чтобы избежать
CORS-нюансов и получать live-reload при желании):

```bash
npx serve .
# или
python3 -m http.server 8000
```

## Как продолжать разработку через Claude Code

1. Распакуйте архив в удобную папку, например `~/projects/industrial-belt`.
2. Откройте терминал в этой папке и запустите `claude` (Claude Code CLI).
3. Дальше можно просто описывать задачи по-русски — Claude Code видит
   `index.html` и весь код целиком, без ограничения на размер, как было
   в чате.
4. Рекомендуется сразу закоммитить текущее состояние в git (см. ниже),
   чтобы потом можно было откатываться и смотреть историю изменений.

```bash
git init
git add -A
git commit -m "Initial import: Индустриальный пояс prototype"
```

## Куда двигаться дальше (не начато, но обсуждалось)

- Несколько локаций и логистика/перевозки между ними.
- Взвешенная модель удовлетворения потребностей — сейчас реализована
  только для класса 1; классы 2–4 используют старую bottleneck-модель
  (min) для своих дополнительных потребностей (o2_mix, stimulant,
  datafeed) поверх унаследованной базы от класса 1.
- Пересмотр структуры навыков: сейчас 5 отраслей = 5 тиров один в один;
  обсуждалась альтернатива — навыки поперёк тиров (Металлургия /
  Электроника / Судостроение / Логистика / Наука).
- Дальнейший баланс: количество рабочих на здание, ставки SP/час,
  лимиты складов (`cap`) — сейчас всё расставлено «на глаз» как
  прототип, не финальные цифры.
- PvP — сознательно отложен, изначально это PvE менеджмент-симулятор.

## Здания, рецепты и навыки (v7)

Здание = универсальная установка, рецепт = что она выпускает.

- Типы (`BUILDING_TYPES`): Добывающая установка, Перерабатывающий завод,
  Гидропонная ферма. Цена и рост цены (x1.15 за каждую установку типа)
  общие для всех рецептов типа.
- Рецепты (`BUILDINGS`): у каждого есть `type`, `unlock` (уровень навыка)
  и при необходимости `skill`. Рецепты T2+ пока без типа (старая схема).
- Установку можно перенастроить на другой открытый рецепт за 10% цены типа.
- Навыки открывают рецепты: Горное дело, Переработка сырья, Гидропоника.
- Тестовое ускорение времени: кнопки внизу страницы (x60 ... x3600).
- Сейв `industrial_belt_v7` (несовместим с v5-v7; сейчас актуален v13).

## Сорта руды (пробно на железе, v8)

Железо добывается в 7 сортах: пыль, шлих, крошка, руда, богатая руда,
магнетитовая руда, самородное железо (`iron_g1` ... `iron_g7`, где `iron_ore` = 4-й).
Каждый сорт открывается уровнем навыка «Горное дело» (0, 1, 1, 2, 3, 4, 5).
Чем лучше сорт, тем меньше его нужно на партию из 3 пластин (12, 9, 7, 5, 4, 3, 2),
но добывается он медленнее (цикл 400-800 с). Итог: с одного бура пластин
от 9 до 27 в час. Плавка сорта — отдельный рецепт `plate_g1` ... `plate_g7`
(навыком не закрыт, показывается, когда сорт есть на складе или открыт).
Богатство месторождения общее на семью (`family:'iron'`).

## Износ и ремонт (v9)

Каждая установка из `BUILDINGS` (весь производственный конвейер T0-T4) имеет
прочность `state.durability[id]`, 100..20%. Падает непрерывно по реальному
времени (примерно -30 п.п. за 45 суток непрерывного существования, независимо
от того, работает установка или простаивает: `DURABILITY_DECAY_PER_SEC`).
Просадка прочности снижает фактический выпуск пропорционально (множится на
уже посчитанный узкий фактор — персонал/быт/сырьё/склад), ниже пола 20%
сама не падает. Чинится кнопкой «Ремонт до 100%» — стоимость около 40% цены
новой установки, пропорционально текущему износу и числу построенных штук
этого рецепта (`repairCost`). При постройке новой штуки и при перенастройке
прочность группы усредняется, а не сбрасывается всем в 100%.
Отдельная тонкая полоска на карточке — чисто визуальный таймер текущего
цикла установки (`data-cyclebar`, обновляется в rAF-цикле `tickCycleBars`,
не завязан на renderAll/симуляцию).
Заодно поправлен баг: проверка заполненности склада у много-рецептных
установок (`plate_g1`...`plate_g7`) читала не тот ресурс (`b.id` вместо
фактического выхода рецепта) и никогда не срабатывала.
Сейв `industrial_belt_v9`.

## Единый весовой склад (v10)

Индивидуальные лимиты (`cap`) на ресурс убраны. У каждого ресурса теперь
`weight` (кг/ед.), а колония делит один общий склад — `WAREHOUSE_BASE_KG=10000`
(10 тонн на старте, дальше расширяется складскими зданиями — пока не сделаны).
`totalCargoWeight()` суммирует вес всех RESOURCES+POP_GOODS, `warehouseFreeKg()`
даёт остаток. `runProdBuilding` считает лимит выхода по остатку общего веса,
делённому на вес выпускаемой единицы (`outMeta.weight`) — значит любой один
раздутый ресурс может забить склад и остановить вообще всё производство,
это единственный источник фактора `storage` теперь.
Новая вкладка «Склад» (первая по счёту, открыта по умолчанию) — сетка
квадратных плиток: иконка, название, количество, вес за единицу; сверху
общая полоска заполнения кг/10000, при переполнении красная. Старая всегда
видимая плашка «Склад колонии» над разделами убрана.
Уточнён цикл добычи железной пыли: 6:17 (377 с) вместо 400 с.
Сейв `industrial_belt_v10`.

## Обратный отсчёт цикла и перетаскиваемый склад (v11)

Под полоской цикла на карточках производства (`.cycle-row`) добавлен текстовый
таймер `MM:SS` до конца текущего цикла установки (`data-cycletime`, считает
`fmtMMSS`). Раньше полоска обновлялась через `requestAnimationFrame`, который
в фоновой/невидимой вкладке браузер сильно троттлит вплоть до полной
остановки — переключил на `setInterval(tickCycleBars, 250)`, обычный таймер
не зависит от фокуса вкладки настолько же сильно и не должен зависать.

Плитки на вкладке «Склад» теперь можно перетаскивать (HTML5 drag-and-drop,
`draggable="true"` + `dragstart/dragover/drop/dragend` на контейнере).
Порядок хранится в `state.warehouseOrder` и переживает перезагрузку;
`warehouseOrder()` подчищает исчезнувшие id и дописывает в конец новые.
Пока идёт перетаскивание, обычная ежесекундная перерисовка склада
приостановлена (`warehouseDragging`), чтобы не выдёргивать плитку из-под
курсора. Работает мышью на десктопе; сенсорный drag на телефоне через
нативный HTML5 DnD не поддерживается браузерами и потребует отдельного
touch-обработчика, если понадобится.

Заодно поправлен более старый баг: `.pop-panel`/`.bgrid` задают `display`
через класс, из-за чего атрибут `hidden` их не скрывал (класс с тем же
приоритетом, но объявленный позже, побеждает дефолтное `[hidden]{display:none}`
браузера) — переключение вкладок могло оставлять контент предыдущей вкладки
видимым под новой. Добавлено глобальное `[hidden]{display:none!important}`.
Сейв `industrial_belt_v11`.

## Главное меню базы: 7 вкладок (v12)

Плоский список разделов заменён на полноценное меню базы (`SECTIONS`),
каждый пункт — отдельная страница/панель:

1. **Штаб-квартира** (`renderHQ`) — обзорная панель: время игры, объекты,
   персонал, склад, текущий изучаемый навык, разбивка построек по тирам.
2. **Здания** (`renderBuildingsStatus`) — только то, что уже построено:
   прочность, кнопка ремонта (теперь 1:1 — процент прочности стоит тот же
   процент цены здания, `REPAIR_FACTOR=1`, было 0.4) и кнопка сноса
   (`tryDemolish`, возвращает `DEMOLISH_REFUND=25%` от цены последней
   построенной штуки этого рецепта, с учётом свободного места на складе).
3. **Построить** (старый `renderBuildings`, урезан) — только рецепт, цена
   и кнопка «Построить»; статус работы, износ, перенастройка сюда не входят.
4. **Рабочие** (`renderPopulation`) — добавлена строка общего населения
   планеты и по каждому расходуемому товару: потребление в час и на сколько
   дней (или часов, если меньше суток) хватит текущего запаса.
5. **Навыки** — без изменений.
6. **Производство** (`renderProduction`, новая) — то, что уже построено и
   работает: полоса загрузки, полоса+обратный отсчёт цикла, перенастройка
   рецепта. Кнопки «Построить» и данных об износе здесь больше нет.
7. **Склад** — без изменений.

Цикл теперь везде, где показан в секундах, подписан ещё и как ММ:СС
(`fmtDuration`) — в «Построить», «Производство» и сервисных карточках
«Рабочих».
Сейв `industrial_belt_v12`.

## Каждая установка — отдельный объект (v13)

`state.buildings[recipeId]` (счётчик) заменён на `state.units` — плоский
список `{id, recipe, builtAt, durability}` для рецептов из `BUILDINGS`
(жильё/сервисные здания/академия остались простыми счётчиками — у них нет
цикла и износа). `state.buildings` сохранён как синхронный кэш количества
(`syncBuildingCount`) — весь код, которому нужна просто цифра (наём
персонала, разблокировка тиров, очки навыков, бейджи), остался нетронутым.

Что реально изменилось:
- Прочность у каждой установки своя, тикает независимо (`decayDurability`
  проходит по `state.units`, не по агрегату).
- Выпуск считается через `effCapacity` — сумму `durability/100` по юнитам
  рецепта, а не через голое число установок. Хуже всех изношенная группа
  из N установок производит меньше, чем N исправных, без отдельного
  штрафующего множителя — износ просто входит в базовую скорость.
- Ремонт (`tryRepairUnit`) и снос (`tryDemolishUnit`) — по конкретному id
  юнита, не по рецепту целиком. «Здания» показывают список юнитов с личной
  прочностью и кнопками.
- Перенастройка (`tryRetoolUnit`) меняет `.recipe` у одного юнита, выбор —
  через выпадающий список на карточке «Производство».
- Обратный отсчёт цикла — теперь по-настоящему свой на каждую установку:
  фаза считается от `unit.builtAt`, а не от общего времени страницы, так что
  семь построенных в разное время экскаваторов показывают семь разных
  таймеров (`tickCycleBars` ищет юнит по id из `data-cyclebar`).
Сейв `industrial_belt_v13`.

## Навыки: 150 уровней вместо 5 (v14)

Старая формула стоимости уровня (`300*level^2.5`, максимум 5 уровней) давала
почти нулевую отдачу первые часы игры и упиралась в стену уже на уровне 2-3.
Переписано под длинную дистанцию:

- `MAX_SKILL_LEVEL=150`. Цена уровня теперь арифметическая, а не экспоненциальная:
  `skillLevelCost(level)=20+15*(level-1)` — level 1 стоит 20 SP (открывается почти
  сразу), level 150 стоит 2255 SP, всего на полную прокачку одного навыка уходит
  ~170 625 SP (по прикидке ~1.5-5 месяцев непрерывной игры в зависимости от
  количества построек и учебных центров).
- Бонусы скорости и сокращения персонала на максимум остались теми же, что были
  на старом уровне 5 (+40% скорость, −25% персонал), просто размазаны на 150
  уровней (`SKILL_SPEED_BONUS=0.40/150`, `SKILL_WORKFORCE_CUT=0.25/150` за уровень) —
  прокачка стала гораздо более гранулярной, без длинных пустых стен между
  ощутимыми апгрейдами.
- Новое: навыки, управляющие добычей на T0 (`t0` Горное дело, `agri` Гидропоника),
  теперь дают ещё и линейную прибавку к богатству месторождения — до +100% на
  максимуме (`SKILL_RICHNESS_BONUS=1.0/150` за уровень, прибавляется к базовому
  случайному богатству `state.richness`, которое раньше было статично весь забег).
  `richOf()` считает это автоматически для любого рецепта через его `recipeSkillId`.
Сейв `industrial_belt_v14`.

## SP на T0 = фактическая добыча, не плоская ставка (v15)

До этой правки любая построенная T0-установка приносила свою долю
`SP_PER_HOUR_BY_TIER[0]=1` в час просто по факту существования — простаивающая
без персонала/сырья/места на складе установка генерировала SP наравне с
работающей на полную. Переписано:

- `spFromT0PerHour()`/`tickSkills()` теперь считают SP по тому же самому
  `producedNow=calc.desiredOut*fraction`, которым в `simulateStep` пополняется
  склад — т.е. **1 реально добытая единица ресурса T0 = 1 SP** (`SP_PER_UNIT_T0`).
  Простой (0% загрузки) даёт 0 SP, частичная загрузка — пропорциональную долю.
  `tickSkills` поэтому переехал в конец `simulateStep`, после того как для всех
  T0-установок посчитан фактический выпуск за тик, а не в начало функции.
- T1-T4 и Академия остались на прежней плоской ставке (`SP_PER_HOUR_BY_TIER`
  без ключа `0`, `ACADEMY_SP_PER_HOUR`) — фактическую привязку просили только
  для T0, здесь её не трогали.
- Цена уровня выведена арифметически из этого же принципа вместо очередной
  выдуманной константы: `skillLevelCost(level) = SP_PER_HOUR_REF_T0_BUILDING*level`,
  где `SP_PER_HOUR_REF_T0_BUILDING` (~38) — сколько добудет **одна-единственная**
  базовая установка (`iron_g1`, пыль, доступна с уровня 0 навыка) за час работы
  на богатстве месторождения 100% без бонуса скорости. То есть в одиночку такая
  установка левелит уровень L примерно за L часов; на практике быстрее — из-за
  бонуса скорости навыка, богатства месторождения (тоже растущего с уровнем,
  см. v14) и нескольких установок разом.
Сейв `industrial_belt_v15`.

## Стоимость уровня — экспонента ×1.7, не линейная (v16)

Линейная кривая v15 (`38*level`) давала слишком ровный, предсказуемый прогресс —
попросили, чтобы каждый следующий уровень был дороже предыдущего на 70%.
Заменено на чистую геометрическую прогрессию:

```
skillLevelCost(level) = round(SKILL_LEVEL_BASE_SP * SKILL_LEVEL_GROWTH^(level-1))
                       = round(20 * 1.7^(level-1))
```

Level 1 = 20 SP, level 5 = 167, level 10 = 2 372, level 20 = 478 145,
level 30 = 96 393 714, level 50 = ~3.9×10¹² — рост без потолка. Уже около
20-25 уровня цена одного уровня перестаёт быть реально достижимой любым
разумным количеством зданий, так что `MAX_SKILL_LEVEL=150` остаётся
формальным потолком переменной, а не ориентиром: экономика игры расчитана
на то, что подавляющее большинство прогресса происходит в первые ~15-20
уровней каждого навыка, дальше — уже "престижная" бесконечная гонка для
тех, кто спустя месяцы игры всё ещё качает через накопленные горы SP.
Прежний линейный расчёт от одной установки (`REF_T0_BUILDING`,
`SP_PER_HOUR_REF_T0_BUILDING`) убран — он был нужен только для старой
формулы стоимости уровня, механика начисления SP (1 добытая единица T0 = 1 SP,
см. v15) не изменилась.
Сейв `industrial_belt_v16`.

## Откат до чистого T0-прототипа (v17)

По просьбе пользователя игра временно свёрнута до одного тира — прорабатываем
цепочку T0 до конца, прежде чем возвращаться к T1-T4. Убрано целиком: все
7 сортов железа, силикат/лёд/водород/уголь/биомасса, весь T1 (пластины,
кремний, графит, жидкий водород, старая вода-рецепт), T2-T4 (сталь, кремниевые
пластины, полимер, электроника, броня, топливные элементы, процессоры, дроны,
реакторы), классы населения 2-4 и все их жильё/сервисные здания/навыки
(Техники/Инженеры/Специалисты, оксигенатор/стимулятор/медиацентр), навыки
T1-T4 и Гидропоника.

Что осталось/добавлено:
- **T0-ресурсы**: `iron_ore` (железная руда), `copper_ore` (медная руда, новый),
  `water` (вода, теперь сама T0-ресурс, а не продукт переработки льда).
- **Здания**: один тип `miner` (Добывающая установка, цена `{iron_ore:60}`,
  ×1.15 за штуку) с тремя перенастраиваемыми рецептами — по одному на каждый
  ресурс. Учебный центр (Академия) тоже переведён на T0-цену.
- **Навыки**: остался только «Горное дело» (`t0`) — он один теперь управляет
  всеми тремя рецептами добычи (по умолчанию `recipeSkillId` = тир рецепта).
- **Население**: только класс 1 (Разнорабочие), единственная потребность —
  вода (раньше это была взвешенная сумма из 4 товаров, еды/одежды/досуга
  пока просто нет в игре).
- **Стартовые запасы**: 300 железной руды, 150 медной руды, 200 воды —
  хватает на несколько первых установок.

UI-правки:
- Циклы производства теперь показываются только как `MM:SS` — убрано сырое
  число секунд, которое раньше стояло рядом (`fmtDuration` используется
  напрямую вместо `b.cycle+' с ('+fmtDuration(b.cycle)+')'`).
- Панель вкладок T0-T4 в разделе «Построить» скрыта, пока `TAB_LABELS`
  состоит из одного элемента (`tabsEl.style.display` учитывает длину массива).
- **Штаб-квартира**: убрана разбивка «построек по тирам» (больше не нужна с
  одним тиром), вместо неё — компактный виджет `renderHQMiniProd()`: список
  работающих установок с именем и тонкой полосой загрузки, без лишних цифр.
- Бейдж «Навыки · ур. X/900» на кнопке раздела убран — считался как сумма
  уровней по всем навыкам к их максимуму, что было бессмысленно при одном
  навыке и вводило в заблуждение.
- Карточка навыка теперь показывает: накопленный бонус (как раньше), плюс
  **новую строку «Каждый уровень даёт»** — то же самое, но за один уровень
  (нужны знаки после запятой, иначе на кону 150 уровней всё округляется до
  0%), плюс **разбивку добычи по каждой активной установке этого навыка**:
  `месторождение % × скорость % × загрузка % = итого %` — месторождение и
  скорость уже включают бонус навыка (богатство аддитивно, скорость
  мультипликативно), загрузка — это текущая фактическая утилизация
  (персонал/склад/износ), тот же `util[b.id].frac`, что двигает полоску на
  карточке производства.
- Ремонт/снос уже были реализованы по каждой установке отдельно (вкладка
  «Здания» — `repairCost`/`demolishCost` + кнопки), под новый набор ресурсов
  адаптировались автоматически, никаких изменений в логике не потребовалось.

Не пересмотрено (сознательно): `computeWorkforce` раньше перебирал классы
жёстко как `[1,2,3,4]`, что упало бы на `HOUSING.find(h=>h.cls===2)` при
пустом списке жилья — переведено на `CLASSES.map(c=>c.id)`, чтобы код не был
завязан на количество тиров/классов и легко расширялся обратно.
